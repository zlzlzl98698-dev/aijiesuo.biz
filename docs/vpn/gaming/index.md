# 游戏加速器与代理机场：UDP 转发、NAT 类型与实测能力边界

> **核心结论（Answer-First）**：很多用户希望“买一个机场同时解决 AI、流媒体和外服游戏联机”。从工程原理来看，**支持 UDP 转发且节点具备 FullCone NAT 的专线机场，可以应付 Steam/Switch/PS5 商店下载、部分合作联机游戏及语音开黑；但对于延迟敏感型竞技游戏（如 Apex、Valorant、CS2、战地等），代理机场无法替代专业游戏加速器**。因为机场的节点路由按大吞吐网页与视频传输设计，缺少针对小包高并发 UDP 的前向纠错（FEC）与多线热备冗余机制。

## 代理机场 vs 专业游戏加速器：底层传输差异

| 维度 | 专业游戏加速器 | 专线代理机场（搭配 Clash TUN / 软路由） |
| --- | --- | --- |
| **核心优化目标** | 最小化单向抖动（Jitter）、零连续丢包、稳定 UDP 会话 | 最大化 TCP/HTTP 吞吐、防封锁伪装、高并发网页/视频加载 |
| **发包与抗丢包机制** | 普遍启用 **多倍发包 / FEC 前向纠错**，哪怕主线丢 1 个小包也能瞬间补全 | 标准单路径隧道转发，一旦跨境段发生短暂拥塞，小包丢包直接表现为游戏“瞬移/掉线” |
| **UDP 与 NAT 处理** | 原生接管游戏进程全部 UDP 端口并主动映射为宽松 NAT（NAT A/1 或 Open） | 需服务端与客户端同时开启 UDP 转发；节点实际 NAT 类型受落地机房防火墙策略限制 |
| **路由颗粒度** | 针对每个游戏大区（日服、港服、新加坡服、韩服）定制游戏服务器 IP 直达专线 | 按国家大区划分落地节点，游戏服务器与落地机房之间可能存在额外绕路 |
| **合规与适用场景** | 仅放行游戏数据与语音（如 Discord 语音部分支持），不可用于浏览网页或 AI | 全能代理网页/应用/AI；兼顾主机商店更新与轻度联机需求 |

## 读懂测速图里的三种 UDP / NAT 类型

在 《2026-08-11 16家机场节点测速方法与边界说明》（第四节第 5 条）中，明确指出 2026 年测速截图展示了各节点的 UDP 测试字段，并真实记录了 **FullCone、RestrictedCone 和 UDP Unknown** 三种结果。它们的工程含义如下：

1. **FullCone（完全圆锥型 NAT / 对应主机 NAT Type A 或 Open）**
   - **含义**：只要内网终端通过代理节点向外建立过一次映射，外部任何主机发往该公网映射端口的 UDP 数据包都能被转发回来。
   - **联机表现**：最理想的联机条件，Switch/PS5/Xbox 联机匹配成功率最高，P2P 房主连接与语音频道最顺畅。
2. **RestrictedCone / Port Restricted（受限圆锥型 NAT / 对应 NAT Type B 或 Moderate）**
   - **含义**：节点只允许你主动发送过数据的外部 IP（或指定 IP+端口）回传 UDP 数据包。
   - **联机表现**：可以进入大多数服务器托管制游戏（Dedicated Server），但部分纯 P2P 联机（如《怪物猎人》《喷射战士》《GTA Online》或部分格斗游戏）会出现找不到房间、频繁踢出或语音连不上的问题。
3. **UDP Unknown（UDP 状态未知 / 未启用或被拦截）**
   - **含义**：测试脚本未检测到有效 UDP STUN 穿透返回。原因可能是该机场落地服务器直接禁用了 UDP 转发（仅放行 TCP），或中转隧道关闭了 UDP 支持，亦或是测试瞬间网络超时。
   - **联机表现**：**完全无法用于绝大多数现代网络游戏联机和实时语音（如 Discord Voice）**，甚至连 QUIC / HTTP/3 协议都会回退降级。

## 如果想用机场兼顾轻度游戏或主机更新，客户端怎么配

1. **桌面端必须开启 TUN 虚拟网卡模式**：绝大多数 PC 游戏和游戏平台客户端（除了浏览器）根本不读取 Windows 系统 HTTP 代理！必须开启 Clash Verge Rev / v2rayN 的 **TUN 模式**（详见 [TUN 模式开启教程](/tutorials/tun/)）才能接管游戏进程的 UDP 流量。
2. **确认机场订阅配置里的 `udp: true`**：检查配置文件中节点项是否开启 UDP 转发，同时注意使用支持完整 UDP 转发的协议（如 VLESS、Trojan、Hysteria 2、支持 UDP 的 Shadowsocks）。
3. **主机玩家（Switch / PS5 / Xbox）需在网关层实现**：手机开热点通常不转发代理，需要通过 PC 端打开 TUN 模式共享网络，或在路由器部署 [OpenClash](/clients/openclash/) / [PassWall2](/clients/passwall2/) / [Nikki](/clients/nikki/) 才能接管游戏机流量。
4. **选区原则**：优先选择物理距离近且直连目标游戏大区的地区节点，如港服选[香港节点](/network/hong-kong/)、日服选[日本节点](/network/japan/)，避免从中国绕道美国再去连日服。

## 常见问题（FAQ）

### 为什么测速时看香港节点延迟只有 25ms，进游戏延迟却显示 80ms 甚至跳红？
测速软件测的是“你的设备 → 机场代理落地机”的 TCP/TLS 延迟；而游戏里显示的延迟是“你的设备 → 代理入口 → 代理落地机 → 远端游戏服务器 → 原路返回”的完整往返 RTT。如果落地机房到游戏服务器之间还要绕网，或者晚高峰 UDP 出现微丢包导致重传，游戏内体感就会明显高于测速表数字。

### Hysteria 2 协议基于 UDP/QUIC，是不是最适合用来打游戏？
不一定。虽然 Hysteria 2 底层使用 QUIC 传输 UDP 数据报，但它的设计初衷是高抗丢包大文件/网页传输，而且部分国内移动和校园网宽带对连续大流量 UDP 存在严苛的运营商 QoS 限速（表现为突然断流 10 秒）。实际打游戏时，走 IEPL 专线的 TCP/UDP 隧道（如 VLESS/Shadowsocks）配合稳定线路，往往比公网直连跑 Hysteria 2 更不易忽高忽低。

### 既然游戏加速器能降延迟，那我可以用游戏加速器代替机场上 Google 或 ChatGPT 吗？
不可以。合规游戏加速器仅对特定白名单游戏端口和服务器 IP 路由放行，不会也无权代理你的普通网页浏览或海外 AI API 请求。
