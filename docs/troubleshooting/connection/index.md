# 连上节点但无法上网（假连接）排查与修复

::: tip 核心结论（Answer-First）
很多用户遇到“客户端测速几十毫秒一切正常，但 Chrome/Edge 打开任何网页都是 `ERR_PROXY_CONNECTION_FAILED` 或 `无法访问此网站`”。这类故障的本质是**流量没有正确进入代理核心的监听端口**。重点排查四件事：**系统代理开关是否打开、浏览器插件是否抢占了端口、系统代理残留旧端口，以及客户端当前处于“直连”还是“规则”模式**。
:::

## 1. 故障表现

- 代理软件主界面显示“已连接”，节点列表测试延迟有正常绿色毫秒数。
- 浏览器（Chrome / Edge / Safari）打开海外网站甚至国内网站全部提示 `ERR_PROXY_CONNECTION_FAILED`、`ERR_CONNECTION_RESET` 或一直处于转圈卡死状态。
- 代理软件的“连接（Connections）”或实时流量监控面板几乎没有任何流量数字波动。

## 2. 可能原因

1. **未开启“系统代理”且未开启 TUN**：仅打开软件选了节点，却忘了打开“系统代理（System Proxy）”总开关，流量依旧直连本地网络。
2. **浏览器代理扩展抢占（极高频）**：浏览器以前安装过 `Proxy SwitchyOmega`、`ZeroOmega` 或其他 VPN 浏览器插件，且扩展正处于“强制接管并指向旧软件端口（如 `10809` 或 `7890`）”状态，与当前运行的新客户端端口（如 `7897`）不一致。
3. **非正常退出导致的系统代理端口残留**：切换不同客户端（如从 v2rayN 切到 Clash Verge Rev）或异常关机后，系统设置里残留着指向已关闭端口的代理地址。
4. **本地混合端口（Mixed Port）被占用**：另一个后台隐身进程占用了 `7890`/`7897` 端口，导致当前客户端核心并未真正监听成功。
5. **代理模式误设为 `Direct（直连）` 或内核启动报错**：配置文件语法有误导致核心未成功拉起。

## 3. 诊断顺序

1. **先看软件日志与运行模式**：确认客户端底部/顶部显示核心正在运行、模式处于 **`Rule（规则）`**，并记录客户端当前设置的“混合端口（Mixed Port）”数字（常见 `7897`、`7890` 或 `10808`）。
2. **用 `curl` 绕过浏览器测试本地端口**：直接在终端指定该端口测试，如果终端能通而浏览器不通，100% 是浏览器插件或系统代理设置问题。
3. **检查系统代理与扩展状态**：对照终端测试结果，核查浏览器扩展及操作系统“网络代理设置”指向的 IP 和端口是否与客户端完全一致。

## 4. 修复步骤

### 步骤 1：禁用冲突的浏览器代理扩展
- 打开 Chrome / Edge 扩展管理页（`chrome://extensions` 或 `edge://extensions`），将 `SwitchyOmega`、免费浏览器 VPN 插件等**全部设为“使用系统代理（System Proxy）”或直接停用**，避免扩展篡改浏览器的请求去向。

### 步骤 2：重置并重开“系统代理”
- 在代理客户端中先**关闭**“系统代理”开关，等待 2 秒再**重新打开**，强制客户端重新向 Windows/macOS 写入正确的 `127.0.0.1:端口号`。
- **Windows 核验路径**：打开系统“设置 → 网络和 Internet → 代理”，确认“使用代理服务器”为开启状态，且地址为 `127.0.0.1`、端口与客户端“设置”里显示的混合端口完全一致（若完全不用代理时应确保此处为关闭状态）。

### 步骤 3：更换未占用的本地监听端口
- 若客户端日志显示 `bind: address already in use` 或系统端口冲突：进入客户端“设置 → 端口设置”，将混合端口改为一个冷门高位端口（如 `17897`），保存后重启客户端并重新打开系统代理。

### 步骤 4：改用 TUN 模式兜底（桌面端进阶）
- 如果部分独立桌面软件依然无视系统代理设置，请按 [TUN 模式开启教程](/tutorials/tun/) 安装服务模式并开启 TUN 虚拟网卡，直接从系统网络层接管全部流量。

## 5. 验证结果

先用终端隔离浏览器干扰做一次直击端口测试，再回到浏览器刷新页面：

```powershell
# Windows PowerShell（将 7897 替换为你客户端实际显示的端口）
# 1. 检查本地端口是否确实处于 Listen 监听状态
netstat -ano | findstr :7897

# 2. 通过该端口请求 Google 204 与 IP 查询
curl.exe -I -x http://127.0.0.1:7897 https://www.google.com/generate_204
```

```bash
# macOS / Linux 终端验证
lsof -i :7897
curl -I -x http://127.0.0.1:7897 https://www.google.com/generate_204
```

当监听命令存在记录、`curl` 返回 `204` 且停用冲突浏览器插件后，网页即可立刻恢复正常加载。
